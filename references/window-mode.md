## 1. 为什么要分窗口形态

模型每一轮都会重读整段对话，不存在一个"设过一次就常驻"的角色状态。由此产生三个可观察的效应，决定了半途窗口的写法：

- **随距离衰减**：角色框架放在最新一条消息里时影响最大；隔几轮之后权重下降。想让它长期生效，得在提示词里写明重申节奏，而不是假设它一直在。
- **叠加而非覆盖**：同一个窗口里出现过多个角色框架后，模型通常跟最新的，但可能混出前一个的语气（例如"审计者"的挑刺口吻渗进后面无关的问答）。
- **压缩会留下半记得的痕迹**：长会话触发上下文压缩时，"用户设定过一个角色"有可能被摘要当成关于这段对话的事实保留，之后以半记半忘的形式影响无关回答。

这三条都是行为层面的普遍规律，具体强度随模型与窗口长度变化，不构成精确阈值。

## 2. 怎么判断是哪一种

按下面任一信号判定为**半途窗口**：

- 窗口里已经有本任务之外的对话内容（闲聊、别的问题、别的任务）。
- 用户用"接着上面""继续""刚才那个"这类指代。
- 用户要求切换角色或换一种工作方式。
- 用户贴进来的是任务描述而不是完整背景，且默认你已知道上下文。

以上都没有、且这是一段新对话的第一条消息，才算**全新窗口**。

## 3. 写进提示词的内容对照

| 维度 | 全新窗口 | 半途窗口 |
|---|---|---|
| 角色框架 | 身份式可用：`<role>你是一名…</role>` | 任务式优先：`<task>本次任务：…</task>`；身份式只在不介意语气延续时用 |
| 上下文块 | 自包含，把背景写全 | 只写窗口里没有的；已知信息用锚点（"沿用上文第 N 条""上一条贴的函数"） |
| 收口句 | 不需要 | 结尾加一句：本次任务完成后，后续对话恢复普通问答 |
| 生效假设 | 按整段窗口有效来写 | 按最近几轮有效来写；需要跨多轮时写明重申节奏 |
| 篇幅 | 按档位正常写 | 更紧：角色块与约束会挤占对话历史 |
| 长任务 | 可在窗口内直接跑 | 优先隔离到新窗口或子代理，只把结果带回来 |

## 4. 改写前后对照

同一个需求：在对话中途让模型审一个函数。

**按全新窗口写（半途窗口里用会出问题）**

```text
<role>你是一名严格的代码审查者，专注边界条件。</role>
<context>我有一份 Python 项目，里面有个 normalize_email 函数，它负责……</context>
<task>审查这个函数的边界条件，按严重程度排序给出问题清单。</task>
```

问题：身份式角色 + 复述背景。在半途窗口里，背景是多余的（窗口已经有了），角色语气还容易延续到后面无关的问答。

**按半途窗口写（推荐）**

```text
<task>本次任务：审查我上一条贴的 normalize_email，只盯边界条件，按严重程度排序给出问题清单。</task>
<scope>只评这个函数，不扩展到调用方与测试文件。</scope>
本次任务完成后，后续对话恢复普通问答。
```

差异：任务式框架、上下文用锚点而不复述、结尾带收口句。

## 5. 反模式清单

- 在半途窗口里写身份式角色 + 长背景复述。
- 复述窗口已知的信息：既浪费 token，也可能和窗口里的真实状态冲突。
- 忘记收口句，让角色语气渗进后续无关对话。
- 把长任务塞进临近压缩的窗口。
- 设一次角色就假设它管到窗口结束。
- 在同一窗口反复叠加不同角色框架。

## 6. 与档位的关系

窗口形态与档位是两条正交的轴：档位决定**写多细**，窗口形态决定**框架、上下文与收口怎么写**。

- 便宜档 + 半途窗口：步骤仍然写死，但角色框架用任务式、背景用锚点。
- 顶级档 + 半途窗口：只给目标与成功标准，同时删掉背景复述、补上收口句。

两条轴的规则冲突时，先满足窗口形态（框架与收口），再按档位调整详略程度。
